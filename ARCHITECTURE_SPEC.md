# TapFlow System & Screen Specification (Final v3)

## 0. Monetization, 7-Day Trial & Pro Entitlement (`:core:billing`)
Monetization Model:
  - Type: Free Tier + 7-Day Free Trial (App-Managed, No Credit Card Required) + One-Time Lifetime Unlock (`ProductType.INAPP`, SKU: `tapflow_pro_lifetime`).
  - Why App-Managed Trial: Google Play Billing supports native free trials only on recurring Subscriptions, not on One-Time Products. Because TapFlow is strictly offline-only with a one-time purchase, TapFlow manages the 7-day trial locally and enforces lifetime ownership via Google Play Billing Library 9.1.0.

Anti-Tamper Local Trial Guardrail:
  - Trial Start Anchor: Stores `trialStartedAtUtcMs` and `maxObservedClockMs` in Preferences DataStore, signed with an HMAC-SHA256 tag generated by a hardware-backed `AndroidKeyStore` secret key.
  - Clock Rollback Protection: If `System.currentTimeMillis() < maxObservedClockMs - 60_000L` OR HMAC verification fails, local trial state is immediately invalidated (`TrialStatus.EXPIRED_TAMPERED`) and prompts for Pro purchase.
  - Trial Duration: Exactly 7 days (`7 * 24 * 60 * 60 * 1000L`) from activation.

Google Play Billing Lifecycle (PBL 9.1.0):
  - Initialization: `BillingClient.newBuilder(context)` MUST configure `.enablePendingPurchases(PendingPurchasesParams.newBuilder().enableOneTimeProducts().build())` and `.enableAutoServiceReconnection()`.
  - Restore & Sync: Queries active `ProductType.INAPP` purchases via `queryPurchasesAsync()` on app launch and `ON_RESUME`. Must handle `PurchaseState.PENDING` gracefully ("Payment pending — Pro will unlock once settled") and call `acknowledgePurchase()` within 3 days for `PURCHASED` state.
  - Note: Do NOT use removed PBL 7 APIs (`querySkuDetailsAsync`, `queryPurchaseHistoryAsync`, parameterless `enablePendingPurchases`).

Entitlement Matrix (Free vs. TapFlow Pro):
  - Free Tier (100% Free Forever — Available permanently after trial expires):
      - Unlimited Scripts, Unlimited Actions per Script, and Unlimited Pipelines (`RunOnce` + `Abort` error handling).
      - ALL Script Actions Unlocked: Tap, Double Tap, Long Press (`Standard`, `Press Down Only`, `Release Only`, `Hold Until`), Multi-Touch, Swipe & Drag (`Linear`, `Bezier Curve`, `Multi-Point Path`), Anti-Ban Jitter (`jitterPx` & `microMovementJitter`), Input Text (`Accessibility SetText`, `Clipboard Paste`, `Human-like Typing`), Delay (`Fixed`, `RandomRange`, `Deviation`), `IfBlock` / `ElseIfBranch` / `Else`, `LoopBlock` (`Count`, `While`, `Until`, `Unlimited`), `Dynamic Variables` & ALL `VariableOp` actions, `KeyEvent`, `LaunchApp`, `ForceStopApp` (falls back safely to Accessibility `HOME` + `killBackgroundProcesses` without Shizuku), `ClipboardOp`, `Vibrate`, `PlayAlertSound`.
      - Basic Conditions & Vision: Single-Point `ColorMatch`, `AppMatch`, `VariableCompare`, Mode 2 Gesture Picker, Mode 3 Live Recording, and Inspect Tab + `Inspect Studio` Single-Pixel Picker + Screenshot Import.
      - Basic Execution Status in Logs (run outcome badges `SUCCESS`/`FAILED`/`STOPPED`, title, timestamp, duration, total steps).
  - TapFlow Pro (Unlocked during 7-Day Trial OR via `tapflow_pro_lifetime` Purchase — 6 Gates):
      - `EXTERNAL_BROADCAST`: MacroDroid / Tasker Broadcast Integration (`TapFlowExternalTriggerReceiver` + `ACTION_EXECUTION_FINISHED` callbacks).
      - `SHIZUKU_SUITE`: Seamless (Shizuku) Suite (shell input, rootless `am force-stop`, shell key events, silent screenshots, auto-grant `PROJECT_MEDIA`).
      - `ADVANCED_VISION`: `ImageMatch` (32-pixel / Fast Template Matching), Multi-Point & Region `ColorMatch`, `Inspect Studio` Crop Region Mode, and Mode 4 Live Image Inspector.
      - `PIPELINE_AUTOMATION`: Pipeline `Loop N` (`iterations > 1`) / `Unlimited` looping and `Skip & Continue` crash recovery.
      - `FULL_LOGS`: Full Execution Logs & Export (JSON/Text log export, expanded per-step traces, condition breakdowns, crash screenshots).
      - `AMOLED_THEME`: AMOLED Pure Black Theme (`Settings Tab`).
  - TapFlow Lifetime Pro Exclusive (`EntitlementState.ProLifetime` ONLY — Excluded from 7-Day Trial — 2 Gates):
      - `DESKTOP_CONSOLE`: Desktop Studio Bridge (`Console Tab` Ktor WebSocket Server).
      - `DATA_BACKUP`: Data Backup & Transfer (`Settings Tab` `.tapflow` Export/Import).

Paywall & Guard Behavior:
  - Paywall Screen / Sheet (`Route.Paywall`):
      - Highlights `"All Actions, Unlimited Scripts & Flows — Forever Free"` alongside remaining Trial countdown (`"7-Day Trial Active (Xd Xh left)"`) OR expired banner, feature comparison checklist distinguishing `[Free]` vs `[7-Day Trial + Lifetime]` vs `[Lifetime Only]`, localized One-Time Price fetched from `ProductDetails` (handling both `oneTimePurchaseOfferDetailsList` and legacy fallback), `[Activate 7-Day Free Trial]` (hidden once trial is active/used), `[Unlock Lifetime Pro]` CTA, and `[Restore Purchase]`.
      - When an active `ProTrial` user opens `Route.Paywall`, highlights `"Upgrade to Lifetime Pro to unlock Desktop Console & Data Backup"`.
  - Soft Feature Guard:
      - Tapping any Pro-locked feature (or tapping Desktop Console or Data Backup without `ProLifetime`) opens `Route.Paywall`.
      - Attempting to Run (`▶`) an imported/existing Script or Pipeline that uses Pro-only features (`ADVANCED_VISION` in Scripts, `PIPELINE_AUTOMATION` or Pro child scripts in Pipelines) after trial expiration blocks execution and prompts `Route.Paywall` (identifying which Pro gates are used).

## 1. Permission Page Specification
Page Architecture & Navigation Flow:
  Header Section:
    - Title: "Permissions Required"
    - Subtitle: "TapFlow requires the following system permissions to perform automated gestures and display floating controls."

  Permission Checklist (Card-based UI):
    # 1. Accessibility Service (Mandatory)
    - Accessibility Permission:
        Type: MANDATORY [Required]
        Purpose: Enables simulated touch input, gestures (tap, swipe), global system key navigation, and foreground app detection.
        Action Trigger: Launches `Settings.ACTION_ACCESSIBILITY_SETTINGS` intent directly targeting TapFlow's service.
        Status Detection: Evaluates `AccessibilityManager.getEnabledAccessibilityServiceList()`.

    # 2. System Overlay Window (Mandatory)
    - Floating Overlay Permission:
        Type: MANDATORY [Required]
        Purpose: Allows the floating control dock and touch inspection loupe to display over other apps and games.
        Action Trigger: Launches `Settings.ACTION_MANAGE_OVERLAY_PERMISSION` intent with `package:${packageName}` URI.
        Status Detection: Evaluates `Settings.canDrawOverlays(context)`.

    # 3. Post Notifications (Mandatory - Android 13+)
    - Post Notification Permission:
        Type: MANDATORY [Required]
        Purpose: Keeps the foreground automation services alive and displays active runner controls in the status bar.
        Action Trigger: Requests runtime `android.permission.POST_NOTIFICATIONS` dialog (Auto-granted on Android 12 and below).
        Status Detection: Evaluates `NotificationManagerCompat.areNotificationsEnabled()`.

    # 4. Ignore Battery Optimizations (Optional / Recommended)
    - Ignore Battery Optimization:
        Type: OPTIONAL [Recommended]
        Purpose: Prevents the Android system from killing background scripts during long AFK sessions.
        Action Trigger: Prompts `Settings.ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` system dialog.
        Status Detection: Evaluates `PowerManager.isIgnoringBatteryOptimizations(packageName)`.

  Restricted Settings Helper (Android 13–16+ Sideload / Enhanced Confirmation Mode Guardrail):
    - Helper Banner / Button: [Blocked by "Restricted Setting"? Open App Info]
        Purpose: On Android 13+ (Accessibility) and Android 15+ (Display over other apps), sideloaded APKs can be locked by Enhanced Confirmation Mode.
        Action Trigger: Launches `Settings.ACTION_APPLICATION_DETAILS_SETTINGS` with `package:${packageName}` URI and shows inline guide ("App Info ➔ Top-right ⋮ menu ➔ Allow restricted settings").

  Lifecycle & Real-time Verification:
    - OnResume Auto-Check:
        - Automatically re-verifies all 4 permissions whenever the user returns to TapFlow from Android System Settings.
        - Updates card status badges dynamically from [Grant Permission] to [Granted ✓] without requiring app restarts.
    - Persistence:
        - When all mandatory permissions are validated, saves `hasCompletedPermissionOnboarding = true` into Preferences DataStore.

  Navigation Controls & Exit Guardrail:
    - Primary Action Button: [Get Started / Continue]
        - State Rule: Strictly DISABLED until all 3 Mandatory permissions (Accessibility, Overlay, Notification) are granted.
        - On Click: Navigates to `Route.Home(HomeTab.SCRIPT)` as single-top start destination and clears backstack.
    - Secondary Action Button: [Exit App]
        - Purpose: Allows users who decline permissions to cleanly exit without being trapped in an infinite loop.
        - On Click: Calls `activity.finishAffinity()` to terminate the application.

## 3. Script Edit & Add Page Specification
Page Architecture & Navigation Flow:
  Top App Bar:
    Left:
      - Navigation Back Icon:
          Behavior: Triggers Navigation Guard. If `isDirty == true`, displays an "Unsaved Changes" confirmation dialog (Discard Changes / Keep Editing / Save & Exit).
    Center:
      - Script Metadata: Editable Script Title (single-line text field) & Script Description (multi-line expandable).
    Right Action Icons:
      - Global Delay Trigger (Free): Opens a Modal BottomSheet to configure script-wide `DelayConfig` (`Fixed` / `RandomRange` / `Deviation`).
      - Dynamic Variables Trigger (Free): Opens a Modal BottomSheet to manage script variables (Key, Type: Text [STRING] / Number [NUMBER] / Yes-No [BOOLEAN], Default Value).
      - Save Script Button: Validates inputs, persists Script and Action tree to Room DB, updates `updatedAt` timestamp, and pops the backstack.

  Action Tree Viewport (Inline Nested Architecture):
    List Layout & Insertion Rules:
      - `LazyColumn` rendering the sequential top-level action list, with inline indented child action containers inside `If Block` (`If Yes / Then Branch`, `Otherwise, if / Else If Branches`, & optional `Otherwise / Else Branch`) and `Loop Block` (`Body Branch`).
      - Persistent `+ Add Step` / `[+ Insert]` buttons located inside every branch and between sibling actions, allowing sequential `IfBlock` placement and nesting up to 3 levels deep.
      - Branch Collapse/Expand: Each `If Block` and `Loop Block` supports collapsing/expanding its child branches to stay readable on mobile portrait screens.
    Action Item Card UI:
      - Leading Section: Hierarchical Step Index Number (e.g., "#01", "#01.1"), Action Type Badge (Color-coded icon + Label).
      - Center Section: Dynamic Value Summary (e.g., "Tap (540, 960) • 50ms", "If [Condition] • 3 Children").
      - Trailing Controls:
          - Move Up Button (▲): Swaps position with the preceding sibling within the same branch (disabled for index 0).
          - Move Down Button (▼): Swaps position with the subsequent sibling within the same branch (disabled for the last index).
          - Edit Action Button (✏️): Opens the action configuration BottomSheet with pre-filled state.
          - Delete Action Button (🗑️): Removes item (and its subtree if container) from the branch with an Undo snackbar prompt.

  Universal Action-Level Post Delay (Applied to all physical interaction actions):
    Configuration Modes:
      - Global (Default): Inherits the script-wide Global Delay setting.
      - Override: Custom delay configured specifically for this step (`DelayConfig`: `Fixed` / `RandomRange` / `Deviation`).
      - Off (0ms): Bypasses delay; immediately triggers the subsequent action.
    Applicable Categories:
      - Touch & Gestures, Input Text, System & Hardware (Key Events, Launch App, Force Stop, Paste).
    Excluded Categories (Strictly 0ms / No Post Delay):
      - Flow Control: If Block, Loop Block, Break, Continue, End Script.
      - All Variable Operations: Set Variable, Math, Random, String, Boolean, Type Casting.
      - Delay Action (Acts as a standalone delay; cannot nest a secondary delay).

## 4. Action Catalog (Add Action BottomSheet)

# Category 1: Touch & Gestures (100% Free)
Touch & Gestures:
  - Tap:
      Parameters:
        - Coordinates (X, Y): Raw Integer inputs or bound Number Variables.
        - Jitter: Random dispersion radius in pixels (Anti-ban protection).
        - Press Duration: Fixed duration (ms) or Randomized Range [Min, Max].
        - Repeat Count: Number of consecutive taps (Default: 1) or Number Variable.
        - Repeat Interval: Interval between consecutive taps (ms) or Randomized Range.
        - Floating Inspector: [Pick via Overlay] button launches Floating Gesture Picker to record (X, Y) on screen.
      Post-Action Delay: Supports Global / Override / Off.

  - Double Tap:
      Parameters:
        - Coordinates (X, Y): Raw Integer inputs or bound Number Variables.
        - Jitter: Random dispersion radius in pixels.
        - Press Duration: Duration of each individual tap (ms).
        - Tap Interval: Gap duration between the first and second tap (ms; typically 80~150ms).
        - Floating Inspector: [Pick via Overlay] button to capture coordinates directly.
      Post-Action Delay: Supports Global / Override / Off.

  - Long Press:
      Parameters:
        - Coordinates (X, Y): Raw Integer inputs or bound Number Variables.
        - Jitter: Initial touch-down radius offset in pixels.
        - Press Duration: Hold duration in milliseconds (ms).
        - Micro-movement Jitter: Toggle + Amplitude (px) simulating subtle human finger trembling during hold.
        - Operation Mode:
            - Standard: Holds for specified duration then releases.
            - Press Down Only / Release Only / Hold Until: Implemented via `AccessibilityManagerBridge` storing `activeStroke: StrokeDescription` with `willContinue = true` and chaining `continueStroke()` segments strictly `< 55,000ms` (to respect Android's 60s `GestureDescription.getMaxGestureDuration()` cap) until released or condition/timeout triggers.

## 7. Floating Window (Overlay Service) Specification
Service Architecture & Window Rules:
  - `OverlayService` (`foregroundServiceType="specialUse"`, Manifest `<property android:name="android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE" ... />`) manages `WindowManager` (`TYPE_APPLICATION_OVERLAY`) powered by `ComposeView`.
  - `MediaProjectionService` (`foregroundServiceType="mediaProjection"`) is strictly decoupled, started ONLY after `ActivityResult` consent and before `getMediaProjection()`, and ONLY when Vision/Capture is required.
  - Orientation & Display Change Handling: `MediaProjectionService` MUST register a `DisplayManager.DisplayListener` to dynamically rebuild `ImageReader` and call `virtualDisplay.resize()` whenever screen orientation or dimensions change (e.g., portrait to landscape gaming).
  - `MediaProjection.Callback.onStop()` Handling: On Android 15+ screen lock or status-bar chip stop, releases `VirtualDisplay`/`ImageReader`, safely pauses active script/capture, and alerts user.
  - Z-Order & Fullscreen Coordinate Alignment:
      - The full-screen transparent capture layer MUST use `FLAG_LAYOUT_IN_SCREEN | FLAG_LAYOUT_NO_LIMITS` and `LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES`, reading **`event.rawX` / `event.rawY`** so captured coordinates align 1:1 with `MediaProjection` screenshots and `dispatchGesture()` (preventing Status Bar offset).
      - Window Z-Order MUST keep the Floating Control Dock strictly **above** the full-screen capture layer at all times (so `[Stop]` and `[Close]` remain clickable).
  - Drag & Drop / Headerless Shadow-Free Icon-First Dock / Idle Passthrough: Magnetic left/right edge snap (automatically re-snaps via `OnLayoutChangeListener` when overlay width/size changes), DataStore `(X, Y)` & `OverlaySizeOption` persistence, headerless vertical strip dock (`0.dp` shadowElevation & tonalElevation with a clean `0.75.dp` `outlineVariant` border, keeping only the top collapse arrow `▲` toggle — drag directly anywhere on the dock surface — followed immediately by mode-essential icons scaled proportionally to `Tiny`/`Compact`/`Medium`/`Large` and ultra-compact numeric counters) collapsible to an icon-only circular bubble, `FLAG_NOT_TOUCH_MODAL | FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCHABLE` on capture layer when idle.

Touch Intercept & Passthrough Execution State Machine (Modes 2, 3, 4):
  1. Intercept Phase: Full-screen transparent capture overlay intercepts `ACTION_DOWN -> ACTION_MOVE -> ACTION_UP`, recording `rawX / rawY`, trajectory, and duration.
  2. Pre-Replay Capture (Modes 3 & 4): Immediately BEFORE replaying the touch (with highlight UI hidden — skipped on Mode 4 swipe/scroll drags), captures clean full-screen frame via `MediaProjection` / Shizuku.
  3. Passthrough Disable Phase: Hides capture window (`View.GONE`) AND sets `FLAG_NOT_TOUCHABLE` with a brief synchronization yield (~40ms) so `InputDispatcher` drops window interception cleanly.
  4. Gesture Replay Phase: Dispatches recorded gesture (tap, long press, or swipe/scroll path) to underlying app via `AccessibilityService.dispatchGesture()` (awaiting `onCompleted()`) or Shizuku.
  5. Restore Phase: Restores capture layer to interceptable state for next gesture ONLY if `sessionState == ACTIVE` (or exits in Mode 2).

Modes & State-Driven Button Visibility (Zero Invalid/Disabled Controls):
  - Mode 1 (Runner): Progress `[Current Top-Level Action / Total Top-Level Actions]` (plus Pipeline `[Step/TotalSteps]` & `[Repeat/TotalRepeats]`).
      - `EXTRA_AUTO_START` (Boolean, default `true`): `OverlayService.ACTION_START_SCRIPT` and `ACTION_START_PIPELINE` launch immediately when `true`; when `false` (`Standby`), `AutomationRunnerEngine.prepareStandbyScript` / `PipelineExecutionEngine.prepareStandbyPipeline` loads the target, seeds in-memory variables, and emits `RunnerPhase.IDLE` (`0/N`) without running yet. `TapFlowExternalTriggerReceiver` (MacroDroid/Tasker) and `TapFlowLocalServer` (`REMOTE_RUN_SCRIPT`) strictly auto-start (`autoStart = true`).
      - `RUNNING`: Shows `[Pause ⏸]`, `[Stop ⏹]`, `[Close ✕]` (hides `[Play ▶]`).
      - `PAUSED`: Shows `[Play/Resume ▶]`, `[Prev ⏮]`, `[Next ⏭]`, `[Stop ⏹]`, `[Close ✕]` (hides `[Pause ⏸]`).
      - `IDLE` / `STOPPED` / `COMPLETED` / `FAILED` / `PAYWALL_BLOCKED`: Shows `[Play ▶]`, `[Prev ⏮]`, `[Next ⏭]`, `[Close ✕]` (hides `[Pause ⏸]` and `[Stop ⏹]`). From Standby `IDLE`, `[Play ▶]` starts immediately, `[Next ⏭]` runs the first action then pauses, and `[Prev ⏮]` enters paused state at action #1.
  - Mode 2 (Gesture Picker): Activated via `[Pick via Overlay]` (`moveTaskToBack`). When `isCaptureActive == true` shows `[Pause ⏸]` + `[Close ✕]`; when `isCaptureActive == false` shows `[Inspect/Resume 🎯]` + `[Close ✕]`. Captures 1 gesture via state machine, writes result to singleton `GesturePickerBridge`, and brings TapFlow back via `FLAG_ACTIVITY_REORDER_TO_FRONT | FLAG_ACTIVITY_SINGLE_TOP` (or `PendingIntent` with `ActivityOptions.MODE_BACKGROUND_ACTIVITY_START_ALLOW_ALWAYS`) without resetting the open Action BottomSheet.
  - Mode 3 (Live Script Recorder): Requires `MediaProjection` (or Shizuku Silent Screenshot). Starts in `STANDBY` (passthrough allowed) showing ONLY `[Record ●]` + `[Close ✕]`. While `ACTIVE`, shows ONLY `[Pause ⏸]`, `[Stop ⏹]`, `[Close ✕]` (+ count). While `PAUSED`, shows ONLY `[Resume ▶]`, `[Stop ⏹]`, `[Close ✕]` (+ count). `[Pause]` preserves recorded actions and `InspectGroup`, adjusts inter-action pause gaps, and allows free navigation; `[Stop]` saves the `Script` and returns to `STANDBY` (`[Close ✕]` saves any captured steps and exits overlay directly on the foreground app). Saves full-screen lossless PNG + clicked pixel color ONLY (`crops = emptyList()`, no auto-cropped PNGs) and starts the inter-action delay timer ONLY after the 1st gesture executes.
  - Mode 4 (Live Image & Target Inspector [Pro]): Requires `MediaProjection` (or Shizuku Silent Screenshot). Starts in `STANDBY` (passthrough allowed) showing ONLY `[Inspect 🎯]` + `[Close ✕]` until user taps `[Inspect]`, which creates a new `InspectGroup`. While `ACTIVE`, shows ONLY `[Pause ⏸]`, `[Stop ⏹]`, `[Close ✕]` (+ count); while `PAUSED`, shows ONLY `[Resume ▶]`, `[Stop ⏹]`, `[Close ✕]` (+ count). `[Pause]` re-enables full touch passthrough while keeping the active `InspectGroup` open so `[Resume]` continues adding items to the exact same group, and `[Stop]` finalizes/clears the group session back to `STANDBY`. During active inspection, taps/long-presses replay cleanly to the underlying app AND capture full-screen 100% Lossless PNG + Foreground App Name/Package + Pixel color ONLY (`crops = emptyList()`; crops are created manually inside `Inspect Studio`), while swipe/drag scrolls replay cleanly to the underlying app without creating spurious tap snapshots.
  - Overlay Close Resource Release & Auto-Close on Return to TapFlow: Closing the overlay (`[Close ✕]`, notification Stop, `ACTION_CLOSE`, `onDestroy`, OR automatically when the user returns to `MainActivity` while `OverlayStateBridge.isOverlayRunning == true` outside brief launch suppression / MediaProjection consent) stops active runner/pipeline jobs, saves any pending `LIVE_RECORDER` actions into Room DB (without re-fronting `MainActivity` on `ACTION_CLOSE`), cancels any pending `GESTURE_PICKER` request (`cancelPendingPick()`), releases any held Accessibility stroke, stops `MediaProjectionService` (`releaseAll()` closing `ImageReader`, `VirtualDisplay`, `DisplayListener`, `MediaProjection`, and foreground notification) unless an independent Desktop Console WebSocket live stream is active, cancels dock animators/display listeners, and removes all `WindowManager` views cleanly. For dock/notification close in `RUNNER_SCRIPT`, `RUNNER_PIPELINE`, `LIVE_RECORDER`, `LIVE_INSPECTOR`, and `IDLE`, closing does **NOT** bring TapFlow to the front—the user remains on their current foreground app/game; **ONLY** `GESTURE_PICKER` dock pick/cancel brings TapFlow back to front.

  - Outgoing Completion / Status Broadcast (`com.jarvis.tapflow.ACTION_EXECUTION_FINISHED`):
      - Sent as an unrestricted standard broadcast (NO `.setPackage(...)` restriction, `FLAG_INCLUDE_STOPPED_PACKAGES`) whenever a Script or Pipeline finishes (`COMPLETED`, `FAILED`, `STOPPED`) while `externalBroadcastEnabled == true` (or triggered externally), or when a trigger fails guardrails (`REJECTED` / `FAILED`).
      - Dot-free Extras (Tasker `%var` compatible): `status`, `mode`, `target_id`, `target_title`, `duration_ms` (Long), `steps_executed` (Int), `error`.
  - Strict Ordered Guardrails (`goAsync()` + cold-start Shizuku binder wait up to ~800ms):

      2. Shizuku installed, `Shizuku.pingBinder()` alive, and permission granted ➔ else `FAILED` (`SHIZUKU_NOT_READY`) + high-priority Notification deep-linking to Seamless tab.
      3. `ShizukuPreferences.externalBroadcastEnabled == true` ➔ else `REJECTED` (`EXTERNAL_TRIGGER_DISABLED`) + Notification.
      4. Accessibility & Floating Overlay permissions granted ➔ else `FAILED` (`PERMISSIONS_MISSING`) + Notification.
      5. Launches `OverlayService` via `ContextCompat.startForegroundService` with Shizuku `am start-foreground-service` fallback.
