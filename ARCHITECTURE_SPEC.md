# TapFlow System & Screen Specification (Final v3)

## 0. Monetization, 7-Day Trial & Pro Entitlement (`:core:billing`)
Monetization Model:
  - Type: Free Tier + 7-Day Free Trial (App-Managed, No Credit Card Required) + One-Time Lifetime Unlock (`ProductType.INAPP`, SKU: `tapflow_pro_lifetime`).
  - Why App-Managed Trial: Google Play Billing supports native free trials only on recurring Subscriptions, not on One-Time Products. Because TapFlow is strictly offline-only with a one-time purchase, TapFlow manages the 7-day trial locally and enforces lifetime ownership via Google Play Billing Library 9.1.0.

Anti-Tamper Local Trial Guardrail:
  - Trial Start Anchor: Stores `trialStartedAtUtcMs` and `maxObservedClockMs` in Preferences DataStore, signed with an HMAC-SHA256 tag generated by a hardware-backed `AndroidKeyStore` secret key.
  - Clock Rollback Protection: If `System.currentTimeMillis() < maxObservedClockMs - 60_000L` OR HMAC verification fails, local trial state is immediately invalidated (`TrialStatus.EXPIRED_TAMPERED`) and prompts for Pro purchase.
  - Trial Duration: Exactly 7 days (`7 * 24 * 60 * 60 * 1000L`) from activation.

Google Play Billing Lifecycle (PBL 9.1.0):
  - Initialization: `BillingClient.newBuilder(context)` MUST configure `.enablePendingPurchases(PendingPurchasesParams.newBuilder().enableOneTimeProducts().build())` and `.enableAutoServiceReconnection()`.
  - Restore & Sync: Queries active `ProductType.INAPP` purchases via `queryPurchasesAsync()` on app launch and `ON_RESUME`. Must handle `PurchaseState.PENDING` gracefully ("Payment pending — Pro will unlock once settled") and call `acknowledgePurchase()` within 3 days for `PURCHASED` state.
  - Note: Do NOT use removed PBL 7 APIs (`querySkuDetailsAsync`, `queryPurchaseHistoryAsync`, parameterless `enablePendingPurchases`).

Entitlement Matrix (Free vs. TapFlow Pro):
  - Free Tier (Available permanently after trial expires):
      - Max 3 Scripts (up to 15 actions per Script) and max 1 Pipeline.
      - Basic Gestures: Tap, Double Tap, Long Press (Standard), Linear Swipe/Drag, Input Text.
      - Fixed Delay (`DelayConfig.Fixed`) and Count Loop (`LoopMode.Count`).
      - Single-Point `ColorMatch`, `AppMatch`, Mode 2 Gesture Picker, Mode 3 Basic Recording.
  - TapFlow Pro (Unlocked during 7-Day Trial OR via `tapflow_pro_lifetime` Purchase):
      - Unlimited Scripts, Actions, and Pipelines.
      - Advanced Vision: `ImageMatch` (32-pixel / Fast Template Matching), Multi-Point / Region `ColorMatch`, and full `Inspect Studio` + Mode 4 Live Image Inspector.
      - Advanced Logic & Variables: `IfBlock` (Card-in-Card nested groups), `While / Until / Unlimited` Loops, and all `Dynamic Variables` & Variable Operations.
      - Anti-Ban Humanization Suite: `Jitter` dispersion radius, `Micro-movement Jitter`, `Bezier Curve` trajectories, `RandomRange` & `Deviation` delays.
      - Seamless (Shizuku) Integration: Shell input injection, rootless `am force-stop` crash recovery, enhanced key events, silent screenshots.
      - Pipeline Watchdog & Logs: Pipeline `Skip & Continue` crash recovery, full Execution History & Crash Screenshots.
      - AMOLED Pure Black Theme (`Settings Tab`, `ProFeatureGate.AMOLED_THEME`).
  - TapFlow Lifetime Pro Exclusive (`EntitlementState.ProLifetime` ONLY — Excluded from 7-Day Trial):
      - Desktop Studio Bridge: Ktor WebSocket Server (`Console Tab`, `ProFeatureGate.DESKTOP_CONSOLE`).
      - Data Backup & Transfer: `.tapflow` Export/Import (`Settings Tab`, `ProFeatureGate.DATA_BACKUP`).

Paywall & Guard Behavior:
  - Paywall Screen / Sheet (`Route.Paywall`):
      - Displays remaining Trial countdown (`"7-Day Trial Active (Xd Xh left)"`) OR expired banner, feature comparison checklist distinguishing `[7-Day Trial + Lifetime]` vs `[Lifetime Only]`, localized One-Time Price fetched from `ProductDetails` (handling both `oneTimePurchaseOfferDetailsList` and legacy fallback), `[Activate 7-Day Free Trial]` (hidden once trial is active/used), `[Unlock Lifetime Pro]` CTA, and `[Restore Purchase]`.
      - When an active `ProTrial` user opens `Route.Paywall`, highlights `"Upgrade to Lifetime Pro to unlock Desktop Console & Data Backup"`.
  - Soft Feature Guard:
      - Tapping any Pro-locked feature (or tapping Desktop Console or Data Backup without `ProLifetime`) opens `Route.Paywall`.
      - Attempting to Run (`▶`) an imported/existing Script or Pipeline that contains Pro actions after trial expiration blocks execution and prompts `Route.Paywall` (identifying which Pro features are used).

## 1. Permission Page Specification
Page Architecture & Navigation Flow:
  Header Section:
    - Title: "Permissions Required"
    - Subtitle: "TapFlow requires the following system permissions to perform automated gestures and display floating controls."

  Permission Checklist (Card-based UI):
    # 1. Accessibility Service (Mandatory)
    - Accessibility Permission:
        Type: MANDATORY [Required]
        Purpose: Enables simulated touch input, gestures (tap, swipe), global system key navigation, and foreground app detection.
        Action Trigger: Launches `Settings.ACTION_ACCESSIBILITY_SETTINGS` intent directly targeting TapFlow's service.
        Status Detection: Evaluates `AccessibilityManager.getEnabledAccessibilityServiceList()`.

    # 2. System Overlay Window (Mandatory)
    - Floating Overlay Permission:
        Type: MANDATORY [Required]
        Purpose: Allows the floating control dock and touch inspection loupe to display over other apps and games.
        Action Trigger: Launches `Settings.ACTION_MANAGE_OVERLAY_PERMISSION` intent with `package:${packageName}` URI.
        Status Detection: Evaluates `Settings.canDrawOverlays(context)`.

    # 3. Post Notifications (Mandatory - Android 13+)
    - Post Notification Permission:
        Type: MANDATORY [Required]
        Purpose: Keeps the foreground automation services alive and displays active runner controls in the status bar.
        Action Trigger: Requests runtime `android.permission.POST_NOTIFICATIONS` dialog (Auto-granted on Android 12 and below).
        Status Detection: Evaluates `NotificationManagerCompat.areNotificationsEnabled()`.

    # 4. Ignore Battery Optimizations (Optional / Recommended)
    - Ignore Battery Optimization:
        Type: OPTIONAL [Recommended]
        Purpose: Prevents the Android system from killing background scripts during long AFK sessions.
        Action Trigger: Prompts `Settings.ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` system dialog.
        Status Detection: Evaluates `PowerManager.isIgnoringBatteryOptimizations(packageName)`.

  Restricted Settings Helper (Android 13–16+ Sideload / Enhanced Confirmation Mode Guardrail):
    - Helper Banner / Button: [Blocked by "Restricted Setting"? Open App Info]
        Purpose: On Android 13+ (Accessibility) and Android 15+ (Display over other apps), sideloaded APKs can be locked by Enhanced Confirmation Mode.
        Action Trigger: Launches `Settings.ACTION_APPLICATION_DETAILS_SETTINGS` with `package:${packageName}` URI and shows inline guide ("App Info ➔ Top-right ⋮ menu ➔ Allow restricted settings").

  Lifecycle & Real-time Verification:
    - OnResume Auto-Check:
        - Automatically re-verifies all 4 permissions whenever the user returns to TapFlow from Android System Settings.
        - Updates card status badges dynamically from [Grant Permission] to [Granted ✓] without requiring app restarts.
    - Persistence:
        - When all mandatory permissions are validated, saves `hasCompletedPermissionOnboarding = true` into Preferences DataStore.

  Navigation Controls & Exit Guardrail:
    - Primary Action Button: [Get Started / Continue]
        - State Rule: Strictly DISABLED until all 3 Mandatory permissions (Accessibility, Overlay, Notification) are granted.
        - On Click: Navigates to `Route.Home(HomeTab.SCRIPT)` as single-top start destination and clears backstack.
    - Secondary Action Button: [Exit App]
        - Purpose: Allows users who decline permissions to cleanly exit without being trapped in an infinite loop.
        - On Click: Calls `activity.finishAffinity()` to terminate the application.

## 3. Script Edit & Add Page Specification
Page Architecture & Navigation Flow:
  Top App Bar:
    Left:
      - Navigation Back Icon:
          Behavior: Triggers Navigation Guard. If `isDirty == true`, displays an "Unsaved Changes" confirmation dialog (Discard Changes / Keep Editing / Save & Exit).
    Center:
      - Script Metadata: Editable Script Title (single-line text field) & Script Description (multi-line expandable).
    Right Action Icons:
      - Global Delay Trigger: Opens a Modal BottomSheet to configure script-wide `DelayConfig` (Normal / Range [Pro] / Deviation [Pro]).
      - Dynamic Variables Trigger (Pro): Opens a Modal BottomSheet to manage script variables (Key, Type: Text [STRING] / Number [NUMBER] / Yes-No [BOOLEAN], Default Value).
      - Save Script Button: Validates inputs, persists Script and Action tree to Room DB, updates `updatedAt` timestamp, and pops the backstack.

  Action Tree Viewport (Inline Nested Architecture):
    List Layout & Insertion Rules:
      - `LazyColumn` rendering the sequential top-level action list, with inline indented child action containers inside `If Block` (`Then Branch` & `Else Branch`) and `Loop Block` (`Body Branch`).
      - Persistent `[+ Add Action]` insertion buttons located at:
          - The head of every branch (Index 0).
          - Between every adjacent action item within the same branch.
          - The tail of every branch (Appends to the end of that branch).
      - Branch Collapse/Expand: Each `If Block` and `Loop Block` supports collapsing/expanding its child branches to stay readable on mobile portrait screens.
    Action Item Card UI:
      - Leading Section: Hierarchical Step Index Number (e.g., "#01", "#01.1"), Action Type Badge (Color-coded icon + Label).
      - Center Section: Dynamic Value Summary (e.g., "Tap (540, 960) • 50ms", "If [Condition] • 3 Children").
      - Trailing Controls:
          - Move Up Button (▲): Swaps position with the preceding sibling within the same branch (disabled for index 0).
          - Move Down Button (▼): Swaps position with the subsequent sibling within the same branch (disabled for the last index).
          - Edit Action Button (✏️): Opens the action configuration BottomSheet with pre-filled state.
          - Delete Action Button (🗑️): Removes item (and its subtree if container) from the branch with an Undo snackbar prompt.

  Universal Action-Level Post Delay (Applied to all physical interaction actions):
    Configuration Modes:
      - Global (Default): Inherits the script-wide Global Delay setting.
      - Override: Custom delay configured specifically for this step (`DelayConfig`: Fixed / RandomRange [Pro] / Deviation [Pro]).
      - Off (0ms): Bypasses delay; immediately triggers the subsequent action.
    Applicable Categories:
      - Touch & Gestures, Input Text, System & Hardware (Key Events, Launch App, Force Stop, Paste).
    Excluded Categories (Strictly 0ms / No Post Delay):
      - Flow Control: If Block, Loop Block, Break, Continue, End Script.
      - All Variable Operations: Set Variable, Math, Random, String, Boolean, Type Casting.
      - Delay Action (Acts as a standalone delay; cannot nest a secondary delay).

## 4. Action Catalog (Add Action BottomSheet)

# Category 1: Touch & Gestures
Touch & Gestures:
  - Tap:
      Parameters:
        - Coordinates (X, Y): Raw Integer inputs or bound Number Variables [Pro].
        - Jitter [Pro]: Random dispersion radius in pixels (Anti-ban protection).
        - Press Duration: Fixed duration (ms) or Randomized Range [Min, Max] [Pro].
        - Repeat Count: Number of consecutive taps (Default: 1) or Number Variable [Pro].
        - Repeat Interval: Interval between consecutive taps (ms) or Randomized Range [Pro].
        - Floating Inspector: [Pick via Overlay] button launches Floating Gesture Picker to record (X, Y) on screen.
      Post-Action Delay: Supports Global / Override / Off.

  - Double Tap:
      Parameters:
        - Coordinates (X, Y): Raw Integer inputs or bound Number Variables [Pro].
        - Jitter [Pro]: Random dispersion radius in pixels.
        - Press Duration: Duration of each individual tap (ms).
        - Tap Interval: Gap duration between the first and second tap (ms; typically 80~150ms).
        - Floating Inspector: [Pick via Overlay] button to capture coordinates directly.
      Post-Action Delay: Supports Global / Override / Off.

  - Long Press:
      Parameters:
        - Coordinates (X, Y): Raw Integer inputs or bound Number Variables [Pro].
        - Jitter [Pro]: Initial touch-down radius offset in pixels.
        - Press Duration: Hold duration in milliseconds (ms).
        - Micro-movement Jitter [Pro]: Toggle + Amplitude (px) simulating subtle human finger trembling during hold.
        - Operation Mode:
            - Standard: Holds for specified duration then releases.
            - Press Down Only / Release Only / Hold Until [Pro]: Implemented via `AccessibilityManagerBridge` storing `activeStroke: StrokeDescription` with `willContinue = true` and chaining `continueStroke()` segments strictly `< 55,000ms` (to respect Android's 60s `GestureDescription.getMaxGestureDuration()` cap) until released or condition/timeout triggers.
        - Floating Inspector: [Pick via Overlay] button to capture coordinates and hold duration.
      Post-Action Delay: Supports Global / Override / Off.

  - Multi-touch [Pro]:
      Parameters:
        - Multi-touch Mode:
            - Custom Points: Touch Points List (X, Y), Jitter, Press Duration, Stagger Delay (ms).
            - Pinch / Spread: Center (X, Y), Start Distance, End Distance, Duration.
            - Rotate: Center (X, Y), Start Angle / End Angle, Radius, Duration.
        - Floating Inspector: [Pick via Overlay] button to record multi-touch anchor positions.
      Post-Action Delay: Supports Global / Override / Off.

  - Swipe & Drag:
      Parameters:
        - Start Point (X1, Y1) & End Point (X2, Y2): Raw values or bound Number Variables [Pro].
        - Jitter [Pro]: Independent start/end randomized radius offset (px).
        - Duration: Traversal time from start to end (ms).
        - Hold Before Drag / Hold After Drag: Touch-down settle delays (ms).
        - Trajectory Mode:
            - Linear: Uniform straight line path (Free).
            - Bezier Curve (Humanized) [Pro]: Configurable curvature offset and randomized control points.
            - Multi-point Path [Pro]: Array of consecutive path coordinates `[(X1, Y1), (X2, Y2), ...]`.
        - Floating Inspector: [Pick via Overlay] button to draw and record drag paths interactively.
      Post-Action Delay: Supports Global / Override / Off.

  - Input Text:
      Parameters:
        - Target Focus: Current Focus or Tap to Focus (X, Y).
        - Text Template: Static text with dynamic variable interpolation (`{order_id}`) & System Tags (`{TIMESTAMP}`, `{DATE}`, `{TIME}`, `{RANDOM_NUM_4}`, `{CLIPBOARD}`).
        - Injection Engine:
            - Accessibility SetText: Instant (0ms) via `ACTION_SET_TEXT` (Native views only).
            - Clipboard Paste: Injects text via system clipboard and `ACTION_PASTE`.
            - Human-like Typing [Pro]: Uses Shizuku `input text` shell if enabled; otherwise uses progressive `ACTION_SET_TEXT` fallback (appending characters incrementally with 50~120ms randomized delay per character).
        - Pre/Post Execution Options: Clear Existing Text, Post Action Key (None / Enter / Search / Send / Done), Auto Hide Keyboard.
      Post-Action Delay: Supports Global / Override / Off.

# Category 2: Flow Control
Flow Control:
  - If Block [Pro]:
      Header Layout & Mechanics:
        - Line 1 (Header): Editable Block Name + Expand/Collapse toggle [▼].
        - Line 2 (Live Natural Language Preview): Positioned at the TOP (e.g., *"When [d] OR ([a] AND [b OR c])"*); doubles as subtitle when collapsed.
        - Line 3 (Root Rule): Top-level logic selector (Match ANY / Match ALL / Match NONE).
      Card-in-Card Architecture (No Code/Brackets):
        - Visual nested cards with depth accent borders (Level 1: Gray ➔ Level 2: Blue ➔ Level 3: Purple).
        - Individual sub-group collapsible state + hard cap at 3 nesting levels.
      Sub-condition Controls:
        - Dual Footer Buttons: `[+ Add Condition]` and `[+ Add Condition Group]`.
      Operator Mappings:
        - AND ➔ Match ALL | OR ➔ Match ANY | NOT ➔ Inline `[IS / NOT]` or `Match NONE`.
      Supported Conditions:
        - Color Match:
            - Single Point `(x, y)` [Free standalone / Pro inside IfBlock], Multi-point [Pro], Multi-point Region `(x1, y1, x2, y2)` [Pro].
            - Rules: ALL / ANY / `% Match` threshold. Tolerance (RGB delta 0~255).
            - Inspect DAO Import: Auto-fills coordinates & HEX color.
        - Image Match [Pro]:
            - Algorithm: 32-pixel match / Fast Template Matching.
            - Search ROI: Bounds `(x1, y1, x2, y2)` or full screen.
            - Inspect DAO Import: Copies the cropped PNG file into a dedicated Script-owned asset directory (so deleting or cleaning items in the Inspect Tab never breaks saved scripts).
            - Tolerance / Similarity slider.
        - App Match:
            - Target: Active foreground app Package Name (detected via `AccessibilityService` `TYPE_WINDOW_STATE_CHANGED`).
            - Picker: Modal BottomSheet with search filter, Coil App Icons, Labels, Package Names (requires `<queries>` in AndroidManifest), plus `[Select Current Foreground App]`.
        - Variable Comparison [Pro]:
            - String (`eq`, `ne`, `contains`, `length gt/lt/eq`), Number (`gt`, `gte`, `lt`, `lte`, `eq`, `ne`), Boolean (`isTrue`, `isFalse`).
      Child Blocks:
        - Then Branch & Else Branch.

  - Delay:
      Parameters:
        - Standalone blocking wait step using `DelayConfig`: Fixed [Free] / RandomRange [Pro] / Deviation [Pro] (Min threshold: 50ms).

  - End Script:
      Parameters: Instantly halts execution of the active script session and resets state.

  - Loop Block:
      Modes:

## 7. Floating Window (Overlay Service) Specification
Service Architecture & Window Rules:
  - `OverlayService` (`foregroundServiceType="specialUse"`, Manifest `<property android:name="android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE" ... />`) manages `WindowManager` (`TYPE_APPLICATION_OVERLAY`) powered by `ComposeView`.
  - `MediaProjectionService` (`foregroundServiceType="mediaProjection"`) is strictly decoupled, started ONLY after `ActivityResult` consent and before `getMediaProjection()`, and ONLY when Vision/Capture is required.
  - Orientation & Display Change Handling: `MediaProjectionService` MUST register a `DisplayManager.DisplayListener` to dynamically rebuild `ImageReader` and call `virtualDisplay.resize()` whenever screen orientation or dimensions change (e.g., portrait to landscape gaming).
  - `MediaProjection.Callback.onStop()` Handling: On Android 15+ screen lock or status-bar chip stop, releases `VirtualDisplay`/`ImageReader`, safely pauses active script/capture, and alerts user.
  - Z-Order & Fullscreen Coordinate Alignment:
      - The full-screen transparent capture layer MUST use `FLAG_LAYOUT_IN_SCREEN | FLAG_LAYOUT_NO_LIMITS` and `LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES`, reading **`event.rawX` / `event.rawY`** so captured coordinates align 1:1 with `MediaProjection` screenshots and `dispatchGesture()` (preventing Status Bar offset).
      - Window Z-Order MUST keep the Floating Control Dock strictly **above** the full-screen capture layer at all times (so `[Stop]` and `[Close]` remain clickable).
  - Drag & Drop / Ultra-Compact Icon-First Dock / Idle Passthrough: Magnetic left/right edge snap, DataStore `(X, Y)` persistence, `~38.dp` vertical icon-first strip dock (`32.dp` compact icon buttons, zero verbose labels or permanent capture hint banners over the game, ultra-compact numeric counters only) collapsible to a `34.dp` semi-translucent icon-only bubble, `FLAG_NOT_TOUCH_MODAL | FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCHABLE` on capture layer when idle.

Touch Intercept & Passthrough Execution State Machine (Modes 2, 3, 4):
  1. Intercept Phase: Full-screen transparent capture overlay intercepts `ACTION_DOWN -> ACTION_MOVE -> ACTION_UP`, recording `rawX / rawY`, trajectory, and duration.
  2. Pre-Replay Capture (Modes 3 & 4): Immediately BEFORE replaying the touch (with highlight UI hidden — skipped on Mode 4 swipe/scroll drags), captures clean full-screen frame via `MediaProjection` / Shizuku.
  3. Passthrough Disable Phase: Hides capture window (`View.GONE`) AND sets `FLAG_NOT_TOUCHABLE` with a brief synchronization yield (~40ms) so `InputDispatcher` drops window interception cleanly.
  4. Gesture Replay Phase: Dispatches recorded gesture (tap, long press, or swipe/scroll path) to underlying app via `AccessibilityService.dispatchGesture()` (awaiting `onCompleted()`) or Shizuku.
  5. Restore Phase: Restores capture layer to interceptable state for next gesture ONLY if `sessionState == ACTIVE` (or exits in Mode 2).

Modes:
  - Mode 1 (Runner): Play/Pause, Previous (`⏮`: decrements top-level action index only; does NOT roll back Variables or external app state), Progress `[Current Top-Level Action / Total Top-Level Actions]`, Next (`⏭`: executes 1 top-level action/block atomically), Stop (`⏹`), Close (`✕`).
  - Mode 2 (Gesture Picker): Activated via `[Pick via Overlay]` (`moveTaskToBack`). Captures 1 gesture via state machine, writes result to singleton `GesturePickerBridge`, and brings TapFlow back via `FLAG_ACTIVITY_REORDER_TO_FRONT | FLAG_ACTIVITY_SINGLE_TOP` (or `PendingIntent` with `ActivityOptions.MODE_BACKGROUND_ACTIVITY_START_ALLOW_ALWAYS`) without resetting the open Action BottomSheet.
  - Mode 3 (Live Script Recorder): Requires `MediaProjection` (or Shizuku Silent Screenshot). Starts in `STANDBY` (passthrough allowed) so users can open their target app before tapping `[Record]`. Supports `Start -> Pause -> Resume -> Stop` (`OverlaySessionState`); `[Pause]` preserves recorded actions and `InspectGroup`, adjusts inter-action pause gaps, and allows free navigation; `[Stop]`/`[Close]` compiles and saves the `Script` and returns to `STANDBY`/TapFlow. Saves full-screen lossless PNG + clicked pixel color ONLY (`crops = emptyList()`, no auto-cropped PNGs) and starts the inter-action delay timer ONLY after the 1st gesture executes.
  - Mode 4 (Live Image & Target Inspector [Pro]): Requires `MediaProjection` (or Shizuku Silent Screenshot). Starts in `STANDBY` (passthrough allowed) until user taps `[Inspect]`, which creates a new `InspectGroup`. Supports `Start -> Pause -> Resume -> Stop`; `[Pause]` re-enables full touch passthrough while keeping the active `InspectGroup` open so `[Resume]` continues adding items to the exact same group, and `[Stop]` finalizes/clears the group session back to `STANDBY`. During active inspection, taps/long-presses replay cleanly to the underlying app AND capture full-screen 100% Lossless PNG + Foreground App Name/Package + Pixel color ONLY (`crops = emptyList()`; crops are created manually inside `Inspect Studio`), while swipe/drag scrolls replay cleanly to the underlying app without creating spurious tap snapshots.
  - Overlay Close Resource Release: Closing the overlay (`[Close ✕]`, notification Stop, or `onDestroy`) stops active runner/pipeline jobs, releases any held Accessibility stroke, stops `MediaProjectionService` (`releaseAll()` closing `ImageReader`, `VirtualDisplay`, `DisplayListener`, `MediaProjection`, and foreground notification) unless an independent Desktop Console WebSocket live stream is active, cancels dock animators/display listeners, and removes all `WindowManager` views cleanly.
